C. Extraction rules — the "regex instructions"

File: app/llm/local.py · these functions encode *how* the deterministic brain reads each field. Each is a mini "instruction" the local Agent-1 follows.

R1 · Deadline resolution (_parse_deadline) rule
📄 file: app/llm/local.py 📍 location: lines 184–231
▼
Field: deadline Precedence: ISO date → "September 11" → MM/DD/YYYY → relative ("next week" / "eow" / "tomorrow" / "today") → plain weekday ("by friday")
Key regex patterns & rules 
1) \b(\d{4})[-/](\d{1,2})[-/](\d{1,2})\b            → ISO-ish date
2) "{month} {day}" / "{day} {month}" forms           → month-name date
3) \b(\d{1,2})/(\d{1,2})/(\d{4})\b (US-friendly)      → numeric date
4) "next week" → today+7 · "eow/this week/end of week" → next Friday
   "tomorrow" → today+1 · "today" → today
5) plain weekday name → next occurrence strictly after today
R2 · Tone matching (_parse_tone) rule
📄 file: app/llm/local.py 📍 location: lines 233–246
▼
Field: tone Rule: canonical word match first, then longest synonym phrase (so "hype energy" beats "energy")
Logic 
for canonical in Tone:  if \b{canonical.value}\b in text → return canonical
for phrase in TONE_SYNONYMS (longest first):  if phrase in text → return its tone
R3 · Audience extraction (_parse_audience) rule
📄 file: app/llm/local.py 📍 location: lines 248–263
▼
Field: target_audience Rule: keyword table (T3), else "targeting <free text>" regex → Title Case
Generic fallback regex 
\btarget(?:ing|s|ed)?\s+(?:the\s+|an?\s+|for\s+)?([a-z][a-z0-9 \-']{1,60}?)
(?=\s*(?:,|\.|$|kinda|with|and|has to|must|ready|by |for ))

R5 · Campaign naming (_campaign_name) rule
📄 file: app/llm/local.py 📍 location: lines 273–289
▼
Field: campaign_name Rule: explicit "name it X" / "campaign called X" / "campaign: X" → else "{Product} Campaign"
3 naming regexes 
(?:name|call|title)\s+(?:it|the campaign|the drop)\s+([A-Za-z0-9][^.,;!?"']{1,60}?)
campaign\s+(?:called|named|titled)\s+["']?([A-Za-z0-9][^.,;!?"]{1,60})
(?:campaign|drop|launch)\s*[:]\s*([A-Za-z0-9][^.,;!?"]{1,60})
→ fallback: f"{product_label} Campaign"

▼
Methods: parse(raw_brief) · repair(raw_brief, issues) Forwards to provider → OpenAI P1/P2/P3 or local R1–R6
